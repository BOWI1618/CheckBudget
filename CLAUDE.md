# CheckBudget — рабочие заметки

Учёт личного и семейного бюджета: мультивалютный, многопользовательский,
с realtime-синхронизацией и офлайн-режимом.

Полное обоснование решений — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
История изменений с причинами — в сообщениях коммитов, они подробные.
Здесь только то, что нужно, чтобы не сломать существующее.

## Команды

```bash
npm run dev          # SQLite, ноль настройки
npm test             # деньги + сквозные тесты на SQLite

npm run db:up        # PostgreSQL 16 в Docker
npm run db:reset     # пересоздать базу: роли, схема, права
npm run test:all     # 99 тестов: SQLite, Postgres, RLS, кластер из двух инстансов
npm run db:down

DATABASE_URL=postgres://checkbudget_app:apppass@localhost:55432/checkbudget npm run dev:server
```

Замеры: `npx tsx bench/seed-large.ts --years 3`, затем `npx tsx bench/load.ts`.
**На демонстрационных 285 операциях никакое узкое место не проявляется** —
замеры на них вводят в заблуждение.

## Инварианты, которые нельзя нарушать

Каждый из них закрыт тестом. Если тест падает — сломан инвариант, а не тест.

**Деньги.** Целые числа в минорных единицах, арифметика конвертации в `BigInt`,
округление ровно один раз. В JSON суммы — строки (поля `*Minor`), клиент
превращает их в числа в одном месте. `float` не появляется нигде.

**Курс замораживается в строке операции.** Обновление справочника не меняет
историю. Смена базовой валюты бюджета — отдельная задача пересчёта, не переключатель.

**Оптимистичные блокировки.** Каждый `PATCH`/`DELETE` требует `version`,
`UPDATE` содержит `WHERE version = ?`, при расхождении — 409 с актуальным
состоянием. Молча перезаписывать чужое изменение нельзя.

**Один запрос — одна транзакция.** Обработчики оборачиваются хуком `onRoute`
в `unitOfWork`. Не обходить: ключ идемпотентности обязан коммититься вместе
с мутацией, иначе повтор клиента создаст дубль.

**Скоуп по бюджету.** Нет метода `getById(id)` — только `getById(budgetId, id)`,
и SQL всегда содержит `WHERE budget_id = ?`. Отсутствие членства — 404, не 403.

**Журнал событий append-only.** На его `seq` держится вся синхронизация.
Политик `UPDATE`/`DELETE` у `events` нет намеренно.

## Postgres: три ловушки, каждая стоила отладки

**Роль приложения не владеет таблицами.** Владелец обходит RLS везде, где нет
`FORCE` — защита исчезает молча, без ошибок в логах. Ролей три:
`checkbudget_owner` (миграции), `checkbudget_app` (приложение),
`checkbudget_replicator` (рассылка событий, читает только журнал и две колонки
`users`). См. `db/postgres/roles.sql`.

**Политики пишутся множествами, а не вызовом функции на строку.**
`USING (is_member(budget_id))` вызывает функцию для КАЖДОЙ строки: на выборке
в 2000 операций это 75 мс против 0,147 мс на сам поиск по индексу.
`USING (budget_id IN (SELECT my_budget_ids()))` планировщик превращает
в хешированный SubPlan — функция вызывается один раз. Разница до 27 раз.

**`INSERT … RETURNING` падает там, где `INSERT` проходит.** Возвращаемая строка
дополнительно проходит SELECT-политику. Если политика чтения опирается только
на членство, создание бюджета падает с ошибкой ЗАПИСИ, хотя виновато чтение.

## Портируемость SQL

Один код работает на SQLite и PostgreSQL; различия заканчиваются в `server/src/db/`.
Расхождения, которые НЕ падают на компиляции:

| Что | SQLite | PostgreSQL |
|---|---|---|
| Булевы значения | Отвергает `true`/`false` | Отвергает `0`/`1` для `BOOLEAN` |
| `SUM(bigint)` | Целое | `numeric`, драйвер отдаёт **строкой** |
| `DATE`, `TIMESTAMPTZ` | Строка | Объект `Date` |
| `substr` по дате | Работает | Функции не существует — нужен `CAST(… AS TEXT)` |
| `GROUP BY` по псевдониму | Разрешён | Требует полных выражений |
| `LIKE` | Без учёта регистра | С учётом — писать `LOWER(x) LIKE LOWER(?)` |
| `INSERT OR IGNORE/REPLACE` | Есть | Только `ON CONFLICT` |

Приведение типов — в драйвере Postgres, прикладной код по движку не ветвится.
**Любое изменение SQL проверяется `npm run test:all`, а не только `npm test`.**

## Асинхронность ломается молча

Слой БД асинхронный. Ошибки, которые не ловит ни компилятор, ни чтение кода:

```ts
{ ...publicUser(id) }        // раскладывание Promise даёт пустоту
if (!isMember(userId, id))   // отрицание Promise ВСЕГДА ложно
await db.get<T>(...)!        // постфикс применяется к Promise
```

Вторая — дыра в безопасности: проверка прав перестаёт работать, а код
выглядит правильным.

## Окружение

- **Node 22.5+** обязателен: используется встроенный `node:sqlite`.
- **`psql` есть только внутри контейнера** — `scripts/pg-reset.sh` ходит через
  `docker exec`.
- Если `docker pull` не работает при живой сети — см.
  `scripts/docker-pull-ipv4.sh` (демон ходит к реестру по IPv6).
