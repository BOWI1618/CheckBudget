# CheckBudget

Учёт личного и семейного бюджета: мультивалютный, многопользовательский,
с синхронизацией между устройствами в реальном времени.

Полное архитектурное описание — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

---

## Запуск

Нужен только Node.js 22.5+. База данных — встроенный SQLite, ставить ничего не надо.

```bash
npm install
npm run demo --workspace=server   # демо-данные: полгода операций, два участника
npm run dev                       # API :3001 + веб :5173
```

Открыть <http://localhost:5173> и войти:

| Пользователь | Пароль | Роль |
|---|---|---|
| `ivan@example.com` | `demo12345` | владелец |
| `anna@example.com` | `demo12345` | участник |

Чтобы увидеть совместное редактирование — откройте приложение в двух окнах
(или на телефоне в той же сети) и добавьте расход в одном из них.

Пустая база вместо демо-данных:

```bash
npm run seed --workspace=server
```

## Две базы данных

Приложение работает и на SQLite, и на PostgreSQL — выбор по переменной окружения:

```bash
npm run dev                                   # SQLite, ноль настройки
DATABASE_URL=postgres://... npm run dev:server  # PostgreSQL
```

Прикладной код одинаков: различия диалектов заканчиваются на границе
`server/src/db/`. Один и тот же набор сквозных тестов прогоняется против обоих
движков — это единственный способ не дать реализациям разъехаться.

Запуск на PostgreSQL локально:

```bash
npm run db:up && npm run db:reset
DATABASE_URL=postgres://checkbudget_app:apppass@localhost:55432/checkbudget npm run demo --workspace=server
```

## Структура

```
shared/   общий код клиента и сервера: деньги, валюты, Zod-схемы
server/   Fastify + WebSocket; слой БД — два драйвера за одним интерфейсом
web/      React + Vite, PWA
db/       роли, DDL и RLS-политики для PostgreSQL
scripts/  pg-reset.sh — пересоздание локальной базы
docs/     архитектура
```

`shared/` существует потому, что денежная арифметика и схемы валидации
обязаны быть одинаковыми на клиенте и сервере: расхождение округлений
между оптимистичным UI и результатом сервера — это ошибка в деньгах.

## Что реализовано

- **Деньги.** Целые числа в минорных единицах, `BigInt` в конвертации,
  округление ровно один раз. `float` не используется нигде, включая JSON:
  суммы передаются строками.
- **Валюты.** RUB по умолчанию; счета и операции в USD, EUR, GBP, CNY и других.
  Курс замораживается в операции — обновление справочника не меняет историю.
- **Совместная работа.** Роли owner / editor / viewer, приглашения по коду,
  проверка прав на сервере при каждом запросе.
- **Realtime.** WebSocket поверх журнала событий с монотонным `seq`:
  переподключение догружает хвост, а не перезагружает данные.
- **Конфликты.** Оптимистичные блокировки по `version`; непересекающиеся
  правки сливаются автоматически, пересекающиеся — показываются пользователю.
  Молчаливой потери изменений нет.
- **Офлайн.** Снимок и очередь мутаций в IndexedDB, идемпотентные повторы,
  PWA с офлайн-оболочкой.
- **Интерфейс.** Mobile-first (нижняя навигация, FAB, добавление расхода
  за три касания) и отдельная десктопная раскладка с сайдбаром,
  многоколоночной сеткой и горячими клавишами.

## Переменные окружения (сервер)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3001` | порт API |
| `DATABASE_FILE` | `data/checkbudget.db` | путь к базе; относительный разрешается от каталога `server/` |
| `JWT_SECRET` | случайный в dev | **обязателен в production** |
| `CORS_ORIGINS` | `http://localhost:5173` | список разрешённых источников |
| `AUTH_RATE_LIMIT_MAX` | `10` | запросов в минуту к `/auth/*` |
| `API_RATE_LIMIT_MAX` | `300` | запросов в минуту к остальному API |

## Путь в продакшен

MVP работает на SQLite и одном процессе. Переход на PostgreSQL —
это замена драйвера в `server/src/db/` и применение `db/postgres/schema.sql`,
который добавляет Row Level Security как второй рубеж защиты доступа.
Прикладной код при этом не меняется. Подробнее — раздел 2.3 архитектуры.

Схема применена к PostgreSQL 16, приложение на нём работает, а 26 тестов
(`npm run test:pg`) проверяют политики.
Они не проверяют «DDL выполняется», а доказывают главное заявление:
запрос без `WHERE budget_id` не отдаёт строки чужого бюджета, подмена id
не даёт доступа, а агрегат `SUM` по всей таблице считает только свой бюджет.

**Важно при развёртывании:** приложение обязано подключаться отдельной ролью,
которая не владеет таблицами и не имеет `BYPASSRLS`. Владелец таблицы обходит
RLS везде, где не включён `FORCE` — и защита исчезает молча, без единой ошибки
в логах. Роли заводятся из `db/postgres/roles.sql`, права выдаются
`db/postgres/grants.sql`, миграции применяет `npm run db:migrate --workspace=server`
с `DATABASE_MIGRATION_URL` от имени владельца схемы.
